# Orgmetra product composition

This service package is the first executable slice of Orgmetra's product-composition boundary tracked by #432. It validates whether configured product routes refer to exact immutable owner API releases before those routes are eligible for a composition generation. Route admission by itself is not buyer or product readiness.

The current contract binds a generation to a deterministic digest of the canonical semantic route projection, rejects same-method route templates that can select the same concrete request, binds each logical `service://` upstream to the exact `owner_release.service_id`, and requires exact owner service/release/OpenAPI/artifact coordinates. Mutable branches, floating release labels, copied owner schemas, reachability-only checks and digest-only pointers do not qualify as route authority. A canonically constructed generation also retains a process-local construction snapshot of its schema, generation identity and configuration digest. Admission revalidates that snapshot plus the current nested route, owner-release and configuration-digest evidence immediately before use, so low-level mutation cannot rewrite the generation identity or coherently retarget the route graph by changing both route material and `config_sha256` after construction.

It does **not** authenticate Keyverse tokens, bind identity subjects to People records, authorize HR resources, proxy HTTP traffic, own retry/idempotency/concurrency policy, query bounded-context databases, or make HR/scientific decisions. Those authorities remain with their existing owners. `AdmissionReceipt` is issued only by the canonical in-process `admit_generation(...)` evaluator; direct construction and low-level unissued objects cannot claim `required_routes_admitted`. Canonical issuance also retains the exact issued field tuple and `required_routes_admitted` fails closed if the receipt's generation/config/route fields are changed after issuance, including through low-level `object.__setattr__` mutation. The receipt and generation construction snapshot are process-local structural integrity evidence only. They are not serialized/durable trust artifacts, HR authorization, or buyer-readiness evidence; a later activation boundary must re-evaluate the exact immutable generation and observed released-owner evidence rather than trust reconstructed or mutated receipt-shaped data.

Current scope is deliberately transport-neutral. The package can sit behind a future released shared edge runtime or another approved ingress without changing its contract. Retry/replay safety is never inferred from a composition-local class; when a runtime slice eventually performs replay, permission must come from the exact released owner operation contract under the observed request state.

Production completion still requires released Keyverse consumer evidence, Orgmetra identity ACLs, real downstream owner OpenAPI/behavior releases, an executable HTTP composition host, security and failure/recovery/rollback evidence, deployment provenance, protected exact-head CI, and full buyer-path performance verification.
