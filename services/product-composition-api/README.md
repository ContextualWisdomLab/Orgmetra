# Orgmetra product composition

This package is the first executable slice of the product-composition boundary tracked by #432. It decides whether configured product routes refer to exact immutable Orgmetra owner API releases before they are eligible for a composition generation. Route admission by itself is not buyer/product readiness.

A generation is bound to a deterministic digest of canonical semantic route material. Configuration identity is minted only after per-route and cross-route invariants pass. Owner release evidence must identify the canonical `ContextualWisdomLab/Orgmetra/releases/tag/<version>` coordinate, each `service_id` has one exact release/OpenAPI/artifact identity per generation, and each logical `service://` upstream must name that same owner service. Mutable branches, floating labels, copied schemas, reachability-only checks, and digest-only pointers are not route authority.

Route identity follows three separate layers:

1. **OpenAPI path-key identity.** OpenAPI Specification 3.2.1 §4.8.1 says templated paths with the same hierarchy but different template names are identical and MUST NOT coexist. `/v1/people/{person_record_id}` and `/v1/people/{worker_record_id}` therefore cannot both acquire configuration identity, even when their HTTP methods differ. Distinct methods may share the same exact template string.
2. **OpenAPI path matching.** The same section, with §4.8.2.1's examples, gives a concrete non-templated path precedence over its templated counterpart. The admission model permits that deterministic overlap only when both routes belong to the same exact owner release and declare the same method set. Thus one owner may publish `GET /v1/people/current` beside `GET /v1/people/{person_record_id}`. Cross-owner concrete/template overlap remains rejected, and ambiguous overlap between two templated paths remains fail-closed rather than depending on framework-specific resolution.
3. **HTTP operation authority.** After path identity/matching are valid, effective method authority is checked separately. RFC 9110 defines HEAD as GET semantics without response content, so GET and HEAD form one selected-resource collision authority while the methods actually declared remain exact contract material.

OpenAPI 3.2.1 §4.8.2 also says each template expression MUST NOT appear more than once in one path template, so `/v1/tenants/{record_id}/people/{record_id}` fails before hashing/admission. Complete RFC 3986 `.` and `..` path segments are rejected rather than normalized into another route identity.

The composition contract has no local retry class, idempotency mode, concurrency mode, HR authorization policy, or scientific truth. Those semantics remain with released owner contracts. `AdmissionReceipt` is issued only by the canonical in-process evaluator; its exact fields and source generation are leased in process-local closure state. Receipt validation rechecks the source generation, nested owner/route evidence, and canonical configuration digest, so post-issuance source mutation invalidates stale evidence.

A canonically constructed `CompositionGeneration` retains a process-local construction snapshot of schema/generation/config identity. One live process cannot give the same `generation_id` two configuration meanings while generation views or canonical receipts remain live. This is not durable allocation authority: after GC/process restart only a future immutable activation/configuration registry can prove historical no-reassignment across deployment lifetimes.

Current scope is transport-neutral and performs no network I/O, authentication, HR-domain authorization, database access, or retry execution. Production completion still requires released Keyverse consumer evidence, Orgmetra identity ACLs, real downstream owner OpenAPI/behavior releases, a deployable HTTP composition host, durable activation/rollback re-admission, security/fault/recovery evidence, supported deployment provenance, protected exact-head CI/review, and full buyer-path k6/E2E including the owner PostgreSQL path with the applicable p95 target.
