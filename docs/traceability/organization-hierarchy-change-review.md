## Boundary note

A passing packet proves only that review evidence satisfies this leaf contract. It does **not** prove that the current parent is still current, that the proposed parent is valid at the mutation coordinate, that the resulting hierarchy is acyclic, or that `recorded_at` came from an authoritative internal system clock. Those facts must be re-established by the authoritative Orgmetra HRIS boundary immediately before any mutation and recorded with immutable audit/outbox evidence.

`recorded_at` is supplied by the invoking boundary. The leaf validates exact built-in fixed-offset temporal shape and rejects a future value at issuance. It does not attest clock provenance. NIST SP 800-53 Rev. 5 Release 5.2.0 AU-8 assigns audit timestamp generation to internal system clocks, so #119 must generate or attest its own authoritative application/audit timestamp after normal #96 integration rather than promoting the packet value into transaction-time authority. Later canonical export validates the retained exact issuance state and digest without re-entering wall-clock freshness, so a backward clock step cannot make already-issued evidence unreadable.

Caller-defined packet classes are rejected at subclass creation, before a subclass can replace `__post_init__`, `__getattribute__`, or another validation/emission hook. Exact primitive checks reject scalar runtime substitution at issuance. Because `frozen=True` is not an unforgeable runtime boundary against low-level `object.__setattr__`, issuance first captures every trust-bearing field once, applies the complete semantic validation contract to that captured snapshot, canonicalizes only those same values, and derives the creation digest plus live-reference key from that snapshot. The issuance concurrency regression pauses after the captured reason has been semantically checked, mutates the retained live object, and proves the mutated value cannot become the sealed reviewed evidence.

The top-level issuance semantic validator is itself part of the trust decision. `_build_packet_runtime()` captures `_validate_issuance_snapshot` before packet construction, and `post_init()` invokes that captured function against the exact issuance snapshot. `test_issuance_validator_binding.py` replaces the later module name with a no-op and proves an invalid same-actor requester/reviewer packet is still rejected. This is intentionally narrower than freezing every validator helper or claiming a general anti-monkeypatch sandbox; deliberate function-global/closure introspection and arbitrary same-process/native execution remain outside the leaf threat claim.

The functions that select that issuance snapshot and turn it into sealed canonical bytes are part of the same trust decision. `_build_packet_runtime()` captures `_snapshot`, `_payload_from_snapshot`, and `_canonical_payload_json`; `post_init()` uses those captured callables so validation, canonicalization, digest creation, issuance state, and live-reference correlation all derive from one runtime-selected snapshot. `test_issuance_snapshot_binding.py` replaces each later module name and proves it cannot redirect issuance to a previously valid snapshot, substitute unrelated payload data, or replace the canonical serialization. This is still only an ordinary module-binding boundary, not a claim that arbitrary same-process code cannot deliberately reach function globals or closure cells.

Issuance is also single-use per live packet identity. Before validation begins, closure-private process-local state atomically rejects an object that is already present in creation evidence or already owns an in-progress issuance reservation. The mutable backing registries and their lock are captured by the packet runtime rather than exported as module-level handles, so ordinary module consumers cannot erase creation evidence or the packet-to-binding retention that keeps a live-reference correlation active. This prevents a low-level-retargeted issued packet from calling `__post_init__()` again under a fresh valid change reference, and prevents two concurrent `__post_init__()` calls from both attempting to seal the same object. The reservation remains process-local defense in depth and is released after a failed first issuance; it is not durable uniqueness or cross-process authorization.

The creation/export digest verifier is constructed with that private runtime rather than looked up through the later module-level `sha256` name. Creation sealing, canonical export comparison, and `sha256_digest()` use the same captured SHA-256 implementation. The digest-binding regression replaces the module name after issuance and proves that a low-level-mutated packet still fails against the original creation seal. This protects an ordinary module capability boundary only; deliberate closure introspection or arbitrary same-process/native code execution is outside the leaf threat claim and belongs to isolation/runtime controls.

Post-issuance payload selection follows the same rule. Issuance stores the exact canonical JSON and an ordered exact issuance state behind the packet runtime. Canonical export captures each retained slot once through the runtime-bound base attribute accessor, compares exact runtime type and value against that issuance state, checks the stored bytes with the captured digest implementation, and returns the issuance JSON only after those checks pass. `test_export_verifier_binding.py` proves that replacing module `_payload` with stale pre-mutation evidence cannot hide a later semantic mutation. The module helper remains a deterministic runtime-type validation seam, not evidence authority.

The export concurrent-mutation regression pauses after the direct slot state is captured, mutates the retained object, and proves the in-flight export still returns the already-issued canonical bytes selected by that snapshot while a subsequent export observes and rejects the changed live state. Representation-preserving runtime subtypes are rejected by exact type comparison rather than treated as equivalent merely because their JSON value matches.

Keeping an unreachable base packet-type branch after subclass creation was sealed would violate the package's owned 100% coverage contract, so packet-class finality lives at class creation. Scalar representation integrity, issuance snapshot integrity, single-use issuance, private issuance-state ownership, private digest-verifier binding, bound issuance-semantic authority, bound issuance-helper authority, private post-issuance payload authority and direct checked-state export are separate executable invariants because a frozen instance can still be modified or re-entered through low-level Python primitives.

The live-reference registry is closure-private process-local defense in depth. It prevents conflicting in-process reissuance while an idempotent packet remains alive, but it does not replace durable tenant-qualified uniqueness or immutable persistence across processes/restarts. The authoritative persistence/audit transaction owns those guarantees.
